# Actionable Track Record Map

Status: Working draft
Last updated: 2026-07-02
Purpose: Explore beyond known projects and convert buried memories into a public-safe, evidence-backed track record.

## Core Idea

Do not start with "What projects do I have?"

Start broader:

1. What problems did I touch?
2. What changed because I was involved?
3. What did I personally own?
4. What proof exists?
5. What can be said safely?
6. Where should this appear: resume, homepage, case study, proof map, timeline, LinkedIn, interview story, or private prep?

The portfolio should show an actionable track record, not just a list of tools.

## The Track Record Funnel

| Stage | Question | Output |
|---|---|---|
| Memory | What happened? | Raw story fragment |
| Ownership | What did I personally do? | Personal contribution |
| Scope | How large or important was it? | Scale, systems, teams, users, reports, tables, workflows |
| Difficulty | Why was it hard? | Constraints, ambiguity, risk, technical challenge |
| Action | What did I build, decide, automate, fix, or explain? | Action verbs and technical specifics |
| Result | What improved? | Metric, recognition, signoff, reuse, trust, speed, quality |
| Evidence | How can I prove it? | Public link, screenshot, message, demo, doc, repo, certificate |
| Boundary | What must stay private? | Redaction/anonymization rule |
| Claim | How should it be worded? | Portfolio-ready statement |

## Broad Exploration Areas

Use this as a radar. Any answer can become a track-record card.

### 1. Delivery Ownership

Look for times where you were trusted with responsibility beyond your title.

Questions:

- What did I own from idea to working output?
- What did I build without another developer carrying the core implementation?
- What did I deliver when requirements were unclear?
- What did someone hand to me because they trusted I would figure it out?
- What project would have slowed down if I was absent?
- What did I demo, document, deploy, or hand over?
- Where did my role title understate my real responsibility?

Possible claim shapes:

- "Owned end-to-end delivery of..."
- "Built the first working version of..."
- "Converted vague requirements into..."
- "Led implementation for..."
- "Unblocked delivery by..."

### 2. Data Engineering Systems

Look for actual systems, not just tools.

Questions:

- What ingestion flows did I build?
- What transformations did I design?
- What validation checks did I create?
- What data layers did I move through: landing, Bronze, Silver, Gold, Warehouse, semantic model?
- What pipelines became reusable?
- What source systems did I work with?
- What tables, reports, files, APIs, or jobs were involved?
- What failure cases did I handle?
- What changed from manual to automated?

Possible claim shapes:

- "Built metadata-driven ingestion for..."
- "Implemented CDC/SCD Type 2 logic using..."
- "Automated validation across..."
- "Standardized source-to-target checks for..."
- "Improved migration reliability by..."

### 3. Reliability, Quality, And Trust

This is a major differentiator for your portfolio.

Questions:

- Where did I reduce errors, discrepancies, failures, or rework?
- What validation or reconciliation logic did I create?
- What did I make more traceable or auditable?
- What reports or pipelines became more trusted?
- What issue kept recurring until I fixed the pattern?
- What did I do to prevent future failures?
- What was the most subtle data quality issue I found?

Possible claim shapes:

- "Reduced validation discrepancies by..."
- "Improved reporting trust by..."
- "Built reconciliation checks for..."
- "Detected and resolved..."
- "Added auditability through..."

### 4. Migration And Modernization

Look for before/after stories.

Questions:

- What legacy system or old process was replaced?
- What was the target system?
- What made migration risky?
- What had to match exactly?
- What had to be redesigned rather than copied?
- What did users/stakeholders need before signoff?
- What was the before/after state?

Possible claim shapes:

- "Modernized legacy reporting from..."
- "Supported migration from... to..."
- "Preserved business trust through..."
- "Rebuilt semantic/reporting layers for..."
- "Created validation paths for migration signoff..."

### 5. Product Engineering And Workflow Design

This captures your unusual software-plus-data angle.

Questions:

- Did I build UI workflows for data work?
- Did I build APIs around data platforms?
- Did I manage forms, review states, approval flows, queues, dashboards, or role permissions?
- Did I integrate Databricks or Fabric through APIs?
- Did I create an internal tool that made work easier?
- Did users interact with the system, not just data outputs?
- What decisions did the product help users make?

Possible claim shapes:

- "Built data-product workflows for..."
- "Created governed review flows for..."
- "Integrated frontend workflows with Databricks..."
- "Designed decision trails for..."
- "Turned backend data logic into a usable product workflow..."

### 6. AI, Automation, And Developer Productivity

Explore beyond hackathon.

Questions:

- Where did I use AI to speed up engineering, analysis, testing, documentation, or support?
- Did I build AI-assisted workflows?
- Did I use Copilot, data agents, semantic models, RAG, prompt libraries, or automated triage?
- Did I connect AI to data safely?
- Did I verify AI responses against source data?
- Did I automate issue detection, summarization, or remediation?
- Did AI help business users ask better questions?

Possible claim shapes:

- "Built AI-assisted workflow for..."
- "Designed verified-response patterns for..."
- "Used semantic models to ground..."
- "Automated issue triage using..."
- "Created prompt and validation patterns for..."

### 7. Business Impact And Stakeholder Value

The track record becomes stronger when tied to people and decisions.

Questions:

- What business decision did my work support?
- What stakeholder pain did it remove?
- Did it help signoff, demo success, client confidence, accreditation, recognition, or sales?
- Did someone use my output to make a decision?
- Did it reduce effort for another team?
- Did it create a reusable asset?
- Did it improve how leadership understood the system?

Possible claim shapes:

- "Enabled faster review of..."
- "Improved stakeholder confidence by..."
- "Supported accreditation/demo/signoff through..."
- "Created reusable assets for..."
- "Helped business teams trust..."

### 8. Recognition, Awards, And External Validation

Do not limit recognition to awards. Small appreciation can become proof.

Questions:

- Who thanked or appreciated my work?
- Was the appreciation from client, manager, architect, leadership, Microsoft, Databricks, or peers?
- Did I receive a rating improvement?
- Did I receive a certificate, badge, mail, Teams message, or meeting mention?
- Did a demo get praised?
- Did a project become a reference asset?
- Did my work help the company earn something?

Possible claim shapes:

- "Recognized by..."
- "Part of a team that won..."
- "Contributed to work appreciated by..."
- "Built solution assets used for..."
- "Improved performance rating from..."

### 9. Communication, Documentation, And Enablement

These are easy to forget and powerful in interviews.

Questions:

- What did I explain to someone non-technical?
- What docs did I create?
- What diagrams did I make?
- What handoff did I prepare?
- Did I train anyone?
- Did I answer client or leadership questions?
- Did I convert complex work into a clear demo?
- Did I create reusable templates or checklists?

Possible claim shapes:

- "Documented..."
- "Created architecture diagrams for..."
- "Prepared demo and handoff material for..."
- "Explained technical tradeoffs to..."
- "Enabled team reuse through..."

### 10. Learning Velocity And Adaptability

Your portfolio can show that you learn and deliver at the same time.

Questions:

- What did I learn while delivering under pressure?
- Which platform did I become productive in quickly?
- Which certification mapped directly to work?
- Where did I move from beginner to owner?
- What did I learn because a project demanded it?
- Which new tool did I use in real delivery first?

Possible claim shapes:

- "Learned and applied..."
- "Became productive in..."
- "Converted certification knowledge into..."
- "Expanded from BI validation into..."
- "Moved from support role to ownership of..."

## Narrowing: From General Memory To Strong Claim

Use this sequence for any raw story.

### Step 1 - Raw Memory

Write one messy sentence.

Example:

> I worked on some report validation and reduced mismatches.

### Step 2 - Concrete Action

Ask: What did I actually do?

Better:

> I wrote SQL reconciliation checks comparing migrated Fabric outputs against report results.

### Step 3 - Scope

Ask: How many, how much, how often, how risky?

Better:

> I validated 15+ migrated reports.

### Step 4 - Result

Ask: What changed?

Better:

> Discrepancies reduced by 90%.

### Step 5 - Claim

Final:

> Validated 15+ migrated BI reports using SQL reconciliation and report-level parity checks, reducing validation discrepancies by 90%.

## General-To-Specific Interview Prompts

Answer these in order when you want to surface new memories.

### Round 1 - Broad Scan

1. What projects, tasks, demos, automations, reports, tools, documents, or fixes did I touch in the last 18 months?
2. Which ones had any visible outcome?
3. Which ones had someone else depending on me?
4. Which ones involved a deadline, demo, client, leadership, or public proof?
5. Which ones did I do mostly by myself?

### Round 2 - Track Record Filter

For each remembered item:

1. Did I build something?
2. Did I fix something?
3. Did I automate something?
4. Did I validate something?
5. Did I migrate something?
6. Did I explain something?
7. Did I receive recognition?
8. Did I create reusable proof?

### Round 3 - Evidence Filter

1. Is there a screenshot?
2. Is there a Git commit?
3. Is there a ticket?
4. Is there a mail or Teams message?
5. Is there a demo deck?
6. Is there a certificate/badge?
7. Is there a public link?
8. Can it be recreated with synthetic data?

### Round 4 - Portfolio Fit

1. Does this prove Data Engineer fit?
2. Does this prove Fabric/Databricks depth?
3. Does this prove BI validation/business impact?
4. Does this prove product engineering depth?
5. Does this prove AI/automation relevance?
6. Does this prove ownership beyond title?
7. Does this prove communication or leadership?
